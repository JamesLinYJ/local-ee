使用 Trivy **rootfs** 的 JAR 识别模式；普通 fs 模式未识别 JAR 的空报告不能算通过。扫描关闭遥测和版本检查，未设置忽略 CVE、严重度过滤或伪造版本记录。Python 审计使用完整已安装版本清单；三个本地源码包单独列出，不把没有公开发布记录当作审计通过。构建／扫描阶段仅查询公开组件和版本，不上传脚本或数据。

`security-downloads.json` / `security-jar-lock.json` 固定直接运行依赖；`security-build-downloads.json` 固定重组工具、原始源与替换组件。`security-runtime-profile.json` 固定四份上游程序集摘要。显式恢复命令只下载并核验；日常分析不下载任何依赖。Jar Jar 使用 ASM 修改真实字节码，构建处理 MR 类、反射字符串、服务名称／提供者和资源；原始 Maven 与许可记录跟随实际替换组件保留。SQLite/Netty 的旧原生资源也必须删除，不能只删 Java 类和版本记录。

完整 CatBoost 类及原生库仍为上游过程构建器的反射签名所需。它没有本轮依赖告警，不能随意裁剪。产品仍拒绝 CatBoost 过程；其文本加载器有两处已知 Spark 4.2 ABI 差异，本次不声明该未开放算法兼容。

本轮还修复了五个应用边界问题：脚本令牌跨父任务访问 openEO 作业、脚本派生进程逃逸生命周期、临时目录缺少合计容量限制、失败上传的未计账残留，以及历史初始化脚本先写密码后 chmod。分别有权限、内核／文件系统、回滚和竞态控制测试；本机运维边界见 [原生部署](native-macos.md)。

验证包括完整 Python 回归、前端类型／构建和测试、24 项实际 JVM 依赖探针、23 项真实 Spark/GeoTrellis 合成多景数值与掩膜对照、NetCDF 数值对齐、封闭表格 CSV 和 Parquet/ORC 往返，以及实际受认证回环 RF/JVM 检查。无原始 Google 同数据对照；合成验收不会修改现有账号、目录或研究结果。

“0”限定为本次数据库和已识别组件的已知漏洞。Mach-O 原生 GDAL/Homebrew 依赖、操作系统和未逐文件审计的供应商源码不能据此宣称无漏洞；未知漏洞、互联网多租户隔离及完整生产验收仍有各自边界。旧 Compose/Docker 配置是历史资料，没有构建、扫描或部署新镜像，不作为本机升级方案。

复现顺序：停止本项目服务，安装／核验原生工具链，恢复固定 JAR，构建引擎并执行加固，重建本地适配器，运行测试与上述实际目录复扫，再启动服务。RF 使用新的 Spark 4.2.0 / SLF4J 2.0.17 锁；已有 RF 安装需重建 base/RF 适配器和清单，不能只改旧清单字段。当前本机没有安装 RF 插件，单独构建和测试的 RF 不自动加入运行目录。
