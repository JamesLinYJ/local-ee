# Finite scalar reducer leaves

This module provides numeric kernels for the bounded static `List.reduce` and inline `FeatureCollection.reduceColumns` subset. It implements the pinned leaves `minMax`, `product`, `stdDev`, `variance`, and `sampleVariance`, with their declared output names. `minMax` returns `min` and `max`; `product` returns `product`; `stdDev` returns `stdDev`; both variance leaves return `variance`. A single output remains a named pair at the kernel boundary so the caller can preserve the reducer's output name while shaping the public scalar result.

Inputs are lists of at most 1,000 values. Nulls are skipped. Other entries must be finite Python `int` or `float` scalars; booleans, nested values, non-finite floats, and integers outside the exact Float64 domain `[-2^53, 2^53]` reject. Work for the input scan, numeric operation, and output names is charged to the existing shared 50,000-step translator budget before allocating the converted-value or result lists. This work charge does not increase any budget.

`stdDev` and `variance` use the population divisor; `sampleVariance` uses the sample divisor. Dispersion uses the existing centered and scaled finite-statistics kernel so large common offsets and opposite-sign large values do not require an overflowing sum of squares. Each leaf computes only its requested output: a finite standard deviation can succeed when its variance is outside Float64, while an unrepresentable variance fails. Variance values below Float64's representable range may round to zero.

Product keeps a normalized binary significand and accumulates exponents separately, avoiding an intermediate overflow or underflow caused only by factor order. A final product outside the finite Float64 range fails; an underflowed final product can round to zero. Negative zero follows the sign of the product.

Local empty and singleton rules are explicit: empty or all-null `minMax` returns null for both names; empty or all-null `product` returns the multiplicative identity `1`; empty dispersion returns null; singleton population `stdDev` and `variance` return zero; singleton `sampleVariance` returns null. These are local finite-list policies and have not been compared against Google Earth Engine. This module does not add raster, weighted, or arbitrary reducer consumers.

The output names follow the pinned [`algorithms.json`](../../../vendor/earthengine-js/algorithms.json) signatures and the official [`ee.Reducer.minMax`](https://developers.google.com/earth-engine/apidocs/ee-reducer-minmax), [`ee.Reducer.product`](https://developers.google.com/earth-engine/apidocs/ee-reducer-product), [`ee.Reducer.stdDev`](https://developers.google.com/earth-engine/apidocs/ee-reducer-stddev), [`ee.Reducer.variance`](https://developers.google.com/earth-engine/apidocs/ee-reducer-variance), [`ee.Reducer.sampleVariance`](https://developers.google.com/earth-engine/apidocs/ee-reducer-samplevariance), and [`ee.List.reduce`](https://developers.google.com/earth-engine/apidocs/ee-list-reduce) references.

The numeric subset now has separate [raster](raster-statistics.md), [static Array](array-statistics.md) and [raster-array](raster-array-statistics.md) consumers. Their shape, grid and NoData contracts are distinct: in particular, all-NoData raster product stays NaN rather than adopting the empty-list identity.
