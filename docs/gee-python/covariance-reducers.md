# Finite covariance reducer leaves

This module adds bounded `Reducer.covariance()` and `Reducer.centeredCovariance()` leaves to static `List.reduce` and inline `FeatureCollection.reduceColumns`. Each row supplies one typed rank-1 `ee.Array` (internal `StaticArray`); ordinary Python lists are EE Lists and are rejected as covariance vectors. Null arrays are skipped after the reducer has checked every non-null vector. The result name is `array`, matching the official eigen-analysis example that reads the reducer result with `covar.get('array')`. Example44 consumes the covariance via `ee.Array(...).eigen()` and independently checks its eigenpairs.

For `covariance`, the local kernel streams observations through Pébay's one-pass update. It anchors the running mean at the first vector, updates the mean of local offsets, then updates the second-moment matrix from the old-mean and new-mean differences. This avoids losing small variation while repeatedly updating a large absolute mean. It returns that matrix divided by `n - 1`, the unbiased sample denominator. Upper-triangle updates are mirrored into an owned, read-only rank-2 `StaticArray`; no list-shaped stand-in is returned.

`centeredCovariance` assumes its input vectors have already been centered. It sums their outer products and divides by `n - 1`; it does not estimate or subtract a mean. The caller is responsible for centering. The official API reference warns that this reducer requires mean-centered data. Neither local reducer verifies that precondition.

Local finite limits are 1,000 input rows and vector width 1..32, with at most 10,000 output cells, rank 8 and 1 MB of JSON output. The kernel precharges input scans, numeric updates, and owned output construction to the existing shared 50,000-step budget. Values must be real and finite; integer cells must fit the exact Float64 range `[-2^53, 2^53]`. Booleans, complex or wider-than-Float64 dtypes, ordinary Lists, mismatched vector dimensions, malformed rows, cycles, and results outside finite Float64 range reject. Empty, all-null, and singleton samples return the named null result because sample covariance is undefined with fewer than two observations. Subnormal-scale results may round to zero.

The online update follows the incremental covariance formulas in Philippe Pébay's [Sandia report SAND2008-6212](https://www.osti.gov/biblio/1028931), which the Google [`ee.Reducer.covariance`](https://developers.google.com/earth-engine/apidocs/ee-reducer-covariance) reference names as its one-pass formula. Local matrix sums use compensated Float64 accumulation around those local differences. This stabilizes common large offsets and ordinary cancellation, but it is not exact arithmetic and is not a Google Earth Engine comparison. The official [`ee.Reducer.centeredCovariance`](https://developers.google.com/earth-engine/apidocs/ee-reducer-centeredcovariance) reference documents the centering precondition and N×N shape; its API page does not specify a denominator, so the local `n - 1` policy is explicit here rather than claimed as verified Google behavior.
