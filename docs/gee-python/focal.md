# Focal image operations

The local compiler supports `Image.focalMin`, `focalMax`, `focalMean`, `focalMedian`, and `focalMode`, including the pinned API's deprecated snake-case algorithm aliases. It also supports `Image.reduceNeighborhood` for one-input, one-output `mean`, `min`, `max`, `median`, and default `mode` reducer leaves. These methods run once per input band. Focal methods retain their band names; neighborhood reduction appends the reducer output name.

The Google API defaults focal calls to a radius of 1.5 pixels, a circle kernel, and one iteration. Local compilation accepts 1–8 iterations and named radii through 16 pixels, which keeps generated masks within 33 by 33 cells. A fixed custom kernel takes precedence over the focal radius and shape. Local compilation supports pixel units only. Named masks use the same bounded local shape constructors as `Kernel.circle`, `square`, `cross`, `plus`, `octagon`, and `diamond`, so each named mask matches its corresponding local `Kernel` mask. Fractional boundaries and these shape rules have not been shown equivalent to Google's server implementation. No Google numerical-parity claim is made. See Google's [focal API reference](https://developers.google.com/earth-engine/apidocs/ee-image-focalmean), [reduceNeighborhood API reference](https://developers.google.com/earth-engine/apidocs/ee-image-reduceneighborhood), and [morphological operations guide](https://developers.google.com/earth-engine/guides/image_morph).

Fixed kernels are bounded to 33 by 33 cells and offsets within 32 pixels. At execution, a nonzero maximum offset must be smaller than both tile dimensions: the pinned GeoTrellis buffer API fails at the equality boundary, which the local planner explicitly rejects. Zero weights do not contribute. Negative weights and empty support reject. Focal filters use positive-weight support and ignore the values of positive weights. `reduceNeighborhood` accepts arbitrary positive weights when `inputWeight='mask'`, because the kernel values are then ignored; for `inputWeight='kernel'` or `'min'`, all positive kernel weights must be identical. Other weight behavior, optimized strategies, composed reducers, and mode reducers with an explicit `maxRaw` limit reject.

Neighborhood output pixels are Float64 through the dedicated `local_ee_focal` process. Both operations require a finite raster source, and distinct source observations must have a proven common grid before the compiler merges them. The output keeps the input image's properties, footprint, spatial grid, and time dimension. Focal methods use `skip_masked=true`; `reduceNeighborhood` follows its `skipMasked` argument, defaulting to true. The compiler conservatively reads the full finite item bounding boxes before applying an export-region mask. The registered dry-run barrier prevents downstream spatial/aggregate constraints and output resampling from pushing across focal. Large item extents can therefore reach the existing native cell/work caps; a smaller export alone does not reduce focal input work. Pixel units refer to this input grid, not the final export resolution. An explicit `Image.clip()` remains part of the image expression and therefore still masks neighbors before a later focal call.

Compiler and SDK serialization tests establish the supported syntax, argument checks, and graph lowering. They do not establish GeoTrellis execution, Google value parity, or production raster acceptance.
