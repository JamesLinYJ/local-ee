# Image.neighborhoodToBands

The pinned Python SDK 1.7.49 can serialize `Image.neighborhoodToBands(kernel)`. The local compiler accepts a nonempty scalar raster image and a fixed pixel `Kernel` with at most 33 by 33 cells. It emits one output band for each nonzero kernel cell, processing input bands in their existing order and each kernel row from left to right, top to bottom. Negative weights select cells; weight magnitudes do not affect the result. A kernel with no nonzero cells is rejected because the local Image contract requires at least one output band.

Output names follow `input_dx_dy`, where `dx = column - focusX` and `dy = row - focusY`. This treats the documented kernel `x` and `y` locations as offsets from the focus. The pinned SDK metadata and Google's [Image.neighborhoodToBands reference](https://developers.google.com/earth-engine/apidocs/ee-image-neighborhoodtobands) describe the names as `input_x_y` and identify x/y as the pixel location in the kernel; the focus-relative interpretation is the local policy. No Google same-data output was used to verify this naming interpretation.

Each output uses the existing Float64 focal process with a one-cell mean and `skip_masked=false`. For a single selected cell, that copies the actual neighbor value and its mask. This lets a valid neighbor populate an output when the center pixel is masked; a masked neighbor remains NoData. The input properties, grid, time keys, and source bounds follow the existing focal path. Consequently, export-region clipping occurs after the full source neighborhood is read, and the local output is Float64 even when the source was integral.

Kernel construction and revalidation, support scans, output names and focal specifications are charged before output bands are allocated. The compiler retains its shared 50,000-step and 1 MB public-result limits. The final lowered process graph still rejects more than 500 nodes; downstream selection can narrow a large intermediate neighborhood expansion before that check. Dense expansions may also exceed the shared work limit during compilation. Array images, source-free constants, unsupported kernels, and generated output-name collisions reject explicitly.

The SDK/compiler tests cover signed support, ignored magnitudes, asymmetric focus and output order, empty support, source and array rejection, ownership, work/output limits, chaining, and mapped time/ROI behavior. These checks establish syntax, compilation, graph metadata, and declared local lowering; they do not establish Google numerical parity. The opt-in `LOCAL_EE_RUN_NEIGHBORHOOD_BANDS_KERNEL_TEST=1` probe feeds compiler-emitted one-offset specs into the actual GeoTrellis Float64 tile kernel and compares every output with an independent whole-grid shift reference. It checks masked-center filling, masked neighbors, and an absent source tile without starting Spark or the service. The current standalone run passed six outputs and 384 pixels; evidence is in `audit/gee-python-wave45/native/neighborhood-bands/20261023T113232Z-dbdf8f3f1c/`. It does not verify Spark scheduling or the complete adapter cube path.
