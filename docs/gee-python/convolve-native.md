# 原生 Float64 `Image.convolve`

内部 GeoTrellis SPI `local_ee_convolve` 对单波段影像的实际 Float64 像元执行一次固定核卷积。输入只接受唯一的 `spec` 字符串参数，输出为带 NaN NoData 的 Float64 单波段 `v`。适配器保留输入的空间键、SpaceTimeKey 时间、栅格网格和立方体产品元数据；上层编译器负责恢复 EE 波段名称。

规格使用最多 32768 字节的 ASCII 紧凑 JSON，且必须符合唯一的规范编码：

```json
{"coefficients":[[-1,0,"3ff0000000000000"],[0,0,"4000000000000000"],[1,0,"bff0000000000000"]],"v":1}
```

Scala 端独立检查版本、字段、重复键、尾随内容、整数类型、规范字节序列和 1–1089 个互异系数。偏移范围是 -32 到 32，严格按 `(dy, dx)` 排序；权重是小写的 16 位原始 IEEE-754 binary64 位模式，必须有限，并拒绝负零。零权重不读取邻值。全零核只允许单个中心正零系数，编译器用它表示空支持；有效中心输出正零。

核按相关运算放置：系数 `(dx, dy)` 读取 `sample(x + dx, y + dy)`，不翻转核，也不按有效邻值重新归一化。掩膜中心始终保持 NoData。有效中心只在所有非零系数对应的邻值都存在且有效时产生结果；缺失 tile、栅格边界或掩膜邻值都会让该输出为 NoData。这是明确的本地完整支持规则，未对照 Google 的缺失邻值行为。

数值内核预先解码各非零权重的绝对整数有效数与二进制指数，并去掉有效数末尾的零位；整个核使用由最小权重指数决定的公共整数单位精确累积乘积。累加器上限随权重范围和系数数目计算：普通系数无需使用最坏情况空间，混有最小亚正规权重和最大有限权重时仍按最多 66 个 64 位 limb 计费。所有乘积在公共单位下相加，最后只做一次最近偶数舍入，保留大乘积相消后的残差、亚正规乘积和舍入边界；最终 Float64 舍入溢出时明确失败。精确零输出为正零。

适配器复用共享栅格键、时间、波段、尺寸、NoData 和有限输入预检；在建立 halo 之前逐 tile 验证输入。halo 半径只由非零系数决定；零半径走原 tile 的直接路径。正半径必须小于 tile 行列中的较小边长，以避开当前锁定版 GeoTrellis 缓冲实现的空裁剪边界。SpaceTimeKey 缓冲只使用同一观测时间。

工作上限沿用 100000 个 tile key、每 tile 10000000 个输入／缓冲单元、总计 100000000 个解码单元，以及每 tile 100000000、总计 1000000000 个运算单位。估算按每个乘积的公共单位移位和累加各计一次动态 limb 遍历，并计入有效数乘法、halo 单元和最终舍入；256×256 的单位权重 3×3 核可通过每 tile 预算，7×7 核会因真实精确点积成本超过现有上限而拒绝。

`tests/test_ee_convolve_kernel.py` 的 opt-in JVM 探针用独立 Python `Fraction.from_float` 全栅格参考，对比手动 halo 与 GeoTrellis collection `BufferTilesRDD` 两条路径的原始 Float64 位。覆盖跨 tile 非对称有符号核、缺 tile／掩膜／零系数、全零核、大乘积精确相消、亚正规值和 ties-to-even、确定性原始位模式随机多系数输入，以及时间键、3×3／7×7 预算读回和最终溢出。探针不启动 SparkContext；它不证明完整 RDD 调度、原生服务／沙箱／浏览器／部署，也不建立 Google 数值等价性。
